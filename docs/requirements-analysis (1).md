**REQUIREMENTS ANALYST**

**1. Problem Statement**

Students on campus frequently lose personal belongings such as
identification cards, phones, books, bags, keys and other valuable
items. When an item is lost, there may be no simple and centralized way
for students to report the loss and search for items that have been
found. Similarly, students who find lost belongings may not know how to
reach the rightful owner.

The **Student Lost-and-Found Mobile Application** aims to provide a
centralized mobile platform where students can report lost or found
items, search and filter reported items, and submit and track claims.
The application will make it easier for students to reconnect with their
belongings while improving the organization and accessibility of
lost-and-found information on campus.

**2. Objectives**

**Main Objective**

To design a user-friendly mobile application that enables students to
efficiently report, search for, and claim lost or found items on campus.

**Specific Objectives**

1.  To allow students to report items they have lost.

2.  To allow students to report items they have found.

3.  To enable users to provide item details and upload images.

4.  To allow students to search for lost and found items.

5.  To provide filtering options to make searching easier.

6.  To allow users to submit claims for items they believe belong to
    them.

7.  To allow users to track the status of their claims.

8.  To provide clear feedback to users after performing important
    actions.

**3. Project Scope**

**In Scope**

The mobile application will include:

- User registration and login.

- Reporting a lost item.

- Reporting a found item.

- Adding descriptions and other details about an item.

- Uploading item images.

- Searching for reported items.

- Filtering search results.

- Viewing item details.

- Submitting an item claim.

- Tracking the status of a claim.

- Providing confirmation and feedback to users.

**Out of Scope**

The project will focus on the **mobile application prototype** and its
interaction design. Full software coding is not required for this HCI
assignment, as the assignment specifically requires a Balsamiq mobile
prototype rather than a fully coded application.

**4. Functional Requirements**

Functional requirements describe what the application should allow users
to do.

  -------------------------------------------------------------------------
  **ID**   **Functional Requirement**
  -------- ----------------------------------------------------------------
  FR1      The system shall allow students to create an account.

  FR2      The system shall allow registered students to log in.

  FR3      The system shall allow users to report a lost item.

  FR4      The system shall allow users to report a found item.

  FR5      The system shall allow users to enter item details when making a
           report.

  FR6      The system shall allow users to upload an image of an item.

  FR7      The system shall display reported lost and found items.

  FR8      The system shall allow users to search for items.

  FR9      The system shall allow users to filter search results.

  FR10     The system shall allow users to view detailed information about
           an item.

  FR11     The system shall allow users to submit a claim for an item.

  FR12     The system shall allow users to track the status of their claim.

  FR13     The system shall provide feedback when an action has been
           successfully completed.
  -------------------------------------------------------------------------

These requirements reflect the assignment\'s required application
functions of reporting lost/found items, adding item details and images,
searching/filtering, and submitting/tracking claims.

**5. Non-Functional Requirements**

Non-functional requirements describe how the application should perform.

  --------------------------------------------------------------------------
  **ID**   **Non-Functional Requirement**
  -------- -----------------------------------------------------------------
  NFR1     **Performance:** The application should respond quickly when
           users navigate between screens.

  NFR2     **Reliability:** The application should provide consistent
           results when users perform searches or submit reports.

  NFR3     **Security:** User account information and submitted information
           should be protected from unauthorized access.

  NFR4     **Availability:** The application should be accessible whenever
           students need to report or search for an item.

  NFR5     **Maintainability:** The application design should be organized
           so that features can be easily updated.

  NFR6     **Compatibility:** The application should be designed
           specifically for smartphone/mobile use.

  NFR7     **Scalability:** The design should be capable of supporting an
           increasing number of users and reported items.
  --------------------------------------------------------------------------

The mobile focus is important because the assignment specifically
requires the project to be designed as a **smartphone mobile
application**.

**6. Usability Requirements**

The application should be easy for students to understand and use,
particularly because users may need to report or search for an item
quickly.

  --------------------------------------------------------------------------
  **ID**   **Usability Requirement**
  -------- -----------------------------------------------------------------
  UR1      The application shall use simple and understandable language.

  UR2      Navigation between major sections shall be clear and consistent.

  UR3      Buttons and interactive elements shall be large enough for
           comfortable touch interaction.

  UR4      The application shall provide clear feedback after important
           actions such as submitting a report or claim.

  UR5      Search and filtering should be simple and easy to use.

  UR6      Forms should clearly indicate required information.

  UR7      The application should minimize unnecessary steps when reporting
           an item.

  UR8      Error messages should clearly explain problems and guide users on
           how to correct them.

  UR9      Information should be organized using a clear visual hierarchy.

  UR10     The design should be accessible and easy to understand for
           different students.
  --------------------------------------------------------------------------

These requirements are consistent with the assignment\'s HCI focus for
the Lost-and-Found application, which includes **mobile forms, search
interaction, feedback, user flows, and error prevention**.

**7. Key User Requirements**

From the perspective of a student, the application should allow them to:

**If I lose something:**

I want to report my lost item with its details and image so that other
students can identify it if they find it.

**If I find something:**

I want to report a found item so that the owner can search for it and
claim it.

**If I am searching:**

I want to search and filter reported items so that I can quickly find an
item that matches mine.

**If I find my item:**

I want to submit a claim and track its status so that I know what is
happening with my claim.

**8. Requirements Summary**

The Student Lost-and-Found Mobile Application will provide students with
a centralized way to **report lost items, report found items, provide
item details and images, search and filter reported items, and submit
and track claims**. The application should prioritize simple navigation,
clear feedback, touch-friendly interaction, error prevention and an
easy-to-understand interface.

The requirements will guide the UX designer and wireframe designer when
creating the personas, user journeys, task flows and Balsamiq prototype.
The assignment requires at least **12 meaningful and linked mobile
screens**, three complete user interaction scenarios, and usability
testing with at least five representative users.
